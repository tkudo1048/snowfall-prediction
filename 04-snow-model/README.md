# 翌日の青森の日降雪量(cm)を、今日までの日別データで予測する

青森・弘前の日別観測データ（今日まで）から、翌日の青森の日降雪量(cm)を予測した。
6つの手法（線形3つ、ランダムフォレスト、勾配ブースティング、SVR）を同じ条件でチューニングし、3つの単純な基準と比べた。

## 結論（評価データ = 2025年11月〜2026年3月の151日）

- どの手法も、3つの基準（持続予測・月別平均・常に0）より平均誤差（MAE）が小さかった。
  - MAE: 3.21〜3.44cm。持続予測は3.97cm、常に0は4.32cm、月別平均は4.48cm。
  - 「常に0」と「月別平均」に対する差は、どの手法でも95%信頼区間が0をまたがない。
  - 「持続予測」に対する差は0.53〜0.76cm。ランダムフォレスト・勾配ブースティング・SVRは区間が0をまたがない（ただし上端は−0.02〜−0.003cmで、ぎりぎり）。線形3つは、日単位の区間だと0をまたぐ。
- 手法どうしの差（最大0.23cm）は、どの組み合わせでも信頼区間が0をまたぐ。この1冬の評価データで「どの手法が一番良いか」は言えない。
- 大雪日（翌日20cm以上）はほぼ当たらない。
  - 予測値が20cm以上の日を「大雪」と判定すると、評価データの大雪日7日のうち当たったのは0日（全手法）。
  - 実際の大雪日でのモデルの予測は平均6.3〜8.4cm。量を小さめに出す。
  - 一番大きな予測は大雪の翌日（実測1cm）に出た。モデルは今日の降雪量に引きずられ、1日遅れで大きく出る傾向がある。
- 翌日の降雪の予測に効いていたのは、主に今日の気温・気圧（低さと、前日からの下がり方）・今日の降雪量。日照・湿度・風は、ほかの項目と情報が重なるためか、評価データ上ではほとんど効いていなかった。

## 実行

```

for s in 42 7 2024; do ../.venv/bin/python tune.py --seed $s --trials 100 --n-jobs 3; done
../.venv/bin/python -W ignore evaluate.py
```

## データと設計

- 地点: 青森・弘前の日別値（気象庁）。`data/raw/aomori_daily.csv`, `hirosaki_daily.csv` を `lib/preprocess.py` の `parse_daily` で数値化。
- 目的変数: 翌日(t+1)の青森の日降雪量(cm)。
- 対象: 予測対象日が11〜3月の日だけ。夏はほぼ0なので、入れると精度が実力以上に良く見えるため。
- 学習データ: 予測対象日が2021-11-01〜2025-03-31（4冬、604日、大雪日25日）。
- 評価データ: 予測対象日が2025-11-01〜2026-03-31（1冬、151日、大雪日7日）。最終評価に1回だけ使った。
- 予測対象日の降雪量が欠測の1日（2024-11-01）は除いた。

### 特徴量（53個。すべて t日 以前の値）

- 青森（t日）: 海面気圧、降水量、1時間降水量の最大、気温（平均・最高・最低）、湿度（平均・最小）、風速（平均・最大・瞬間）、日照時間、降雪量、最深積雪
- 青森の風向: 最大風速・最大瞬間風速の風向を「北寄りほど+」「東寄りほど+」の2つの数に分けたもの。風向は「北」「北北東」…の文字なので、角度に直して数として扱えるようにした。
- 青森の変化: 気温の日較差、前日からの気温・湿度・気圧・積雪の変化（t−1 → t）
- 青森の天気（t日の昼）: 雪/みぞれ・雨・雷を含むか、晴で始まるか
- 青森の天気（t−1日の夜）: 雪/みぞれを含むか
- 弘前（t日）: 降水量、気温（平均・最高・最低）、湿度（平均・最小）、風速（平均・最大）、日照時間、降雪量、最深積雪、最多風向（2成分）、前日からの気温の変化
- 前日・数日間: 青森の前日（t−1）の降雪量・平均気温・湿度・日照、3日間（t−2〜t）の降雪量の合計
- 青森と弘前の気温差
- 気温の折れ線: max(0, 2℃ − 日平均気温)（青森・弘前）と、それ×青森の湿度。データ分析で分かった「日平均気温が約2℃以上だと雪はほぼ0」を、直線しか表せない線形モデルでも表せるようにするための項目。
- 季節: 予測対象日の通算日を sin/cos に直したもの（暦なので事前に分かる）

### リーク対策（未来の情報が混ざらないように）

- t+1日の値は使わない。「翌日への気圧変化」も使わない。
- t日の「天気概況（夜）」は使わない。気象庁の日別値では夜 = 18時〜翌日6時なので、予測対象日の0〜6時の天気が入ってしまう。代わりに t−1日の夜（t日の6時まで）を使った。
- 欠損の穴埋め（中央値）・標準化・月別平均の計算は、学習に使う範囲のデータだけで行う（パイプラインの中で計算）。
- 予測は「t日が終わった時点（24時）」で行う想定。

### 分割とチューニング

- 時系列のまま分割し、シャッフルはしない。
- チューニングは学習データの中だけで、冬単位で前向きに3回検証した（CV = 交差検証。学習データを分けて「学習→検証」を繰り返し、未知のデータへの強さを見積もる方法）。
  - 2021年の冬で学習 → 2022年の冬で検証
  - 2021〜2022年の冬で学習 → 2023年の冬で検証
  - 2021〜2023年の冬で学習 → 2024年の冬で検証
- CVスコア = 3回の検証MAEの平均。Optuna（TPESampler、過去の試行結果から次に試す値を賢く選ぶ方法）でこれを最小にした。
- 探索予算: 全手法とも100試行。seed 42を主結果とし、確認のためseed 7・2024でも同じ探索をした。
- 最良パラメータで学習データ全体（4冬）に学習し直し、評価データで1回評価した。

## 手法（どれも scikit-learn）

- Ridge回帰: 特徴量に重みを掛けて足すだけの直線的なモデル（線形モデル）。重みが大きくなりすぎないようにブレーキ（正則化）をかける。重みを見れば何が効いているか読める。特徴量は平均0・標準偏差1に揃えて（標準化）から使う。
- Ridge回帰（気温の折れ線なし）: 上の「気温の折れ線」3項目を抜いたもの。折れ線の効果を見るための比較用。
- ElasticNet: Ridgeに、不要な特徴量の重みをちょうど0にする働き（Lasso）を混ぜた線形モデル。
- ランダムフォレスト: 「もし気温が○℃以下なら…」と条件で分けていく決定木を、データを少しずつ変えて100本以上作り、平均するモデル。
- 勾配ブースティング（HistGradientBoosting）: 決定木を1本ずつ足し、前の木の間違いを次の木で直していくモデル。
- SVR（RBFカーネル）: データどうしの「近さ」をもとに、曲がった関係も表せる回帰モデル。標準化してから使う。

### ゼロが多いことへの対処（全手法で同じ条件）

- 目的変数を log1p 変換（log(1+降雪量)）して学習するかどうかを、全手法で同じ選択肢としてOptunaに選ばせた。右に裾の長い分布を縮め、大雪の日の極端な値に引きずられにくくするため。
- 結果: seed 42では全手法で log1p 変換ありが選ばれた（seed 7のSVRだけ変換なし）。
- Poisson/Tweedie損失は、SVRに同じものがなく条件を揃えられないため使っていない。
- 予測が0未満になったら0に切った（全手法・全基準で共通）。

### 探索範囲

- Ridge: alpha 1e-3〜1e4（対数）
- ElasticNet: alpha 1e-4〜10（対数）、l1_ratio 0.05〜1
- ランダムフォレスト: 木の数 100〜600、深さ 2〜20、葉の最小サンプル数 1〜50、使う特徴量の割合 0.1〜1
- 勾配ブースティング: 学習率 0.005〜0.3、木の数 50〜800、葉の数 4〜64、葉の最小サンプル数 5〜100、L2正則化 1e-6〜10、使う特徴量の割合 0.2〜1
- SVR: C 0.01〜1000、epsilon 0.001〜3、gamma 1e-4〜1（いずれも対数）

## 基準（これより良くなければモデルを作る意味がない、という比較相手）

- 持続予測: 「翌日も今日と同じ降雪量」
- 学習データの月別平均: 予測対象日の月の、学習データでの平均降雪量
- 常に0: 毎日「降らない」と予測する。冬でも約半分の日は降雪0なので、MAEでは意外と手ごわい

## 指標の意味

- MAE（平均絶対誤差）: 予測と実際の差（cm）の絶対値の平均。「平均して何cmずれるか」。小さいほど良い。
- RMSE（二乗平均平方根誤差）: 差を2乗して平均し、ルートを取ったもの。大きく外した日を重く数える。小さいほど良い。
- R²（決定係数）: 「毎日、評価期間の平均値を予測する」場合と比べて、ずれの2乗をどれだけ減らせたか。1が完璧、0が平均と同じ、マイナスは平均より悪い。
- 大雪日の検出（翌日20cm以上を「大雪日」とする）
  - AUC: 大雪日と大雪でない日を1つずつ選んだとき、大雪日の方に大きな予測値を出せている確率。0.5で当てずっぽう、1で完璧。
  - AP（平均適合率）: 予測値の大きい順に並べたとき、上位に大雪日が集まっているか。当てずっぽうだと大雪日の割合（評価データでは7/151 = 0.046）になる。
  - 適合率: 「大雪」と予測した日のうち、本当に大雪だった割合。
  - 再現率: 本当の大雪日のうち、「大雪」と予測できた割合。
  - 判定の閾値は2通り。(1) 予測値20cm以上。(2) 学習データのCVの予測で、大雪日の判定のF1（適合率と再現率のバランス）が最大になる値。(2)は評価データを見ずに決めた。

### 大雪日の検出（評価データの大雪日は7日）

- 持続予測は7日を「大雪」とし、当たりは1日（適合率0.143、再現率0.143）。

- Ridge回帰（折れ線なし）: 5.95cm → 21日、0.238、0.714

- ランダムフォレスト: 4.02cm → 35日、0.171、0.857

### 差は本物か（評価データのブートストラップ、5000回）

評価期間の日をランダムに選び直して（復元抽出）MAE差を計算し直し、ばらつきの幅（95%信頼区間）を出した。
日は連続していて独立ではないため、1日単位と、7日ずつの塊（循環ブロック）単位の両方で行った。値は「A − B」で、負ならAの方が誤差が小さい。

持続予測との差（日単位の区間 / 7日ブロックの区間）:
- Ridge: −0.593（−1.281〜+0.082 / −1.168〜−0.050）
- Ridge（折れ線なし）: −0.558（−1.213〜+0.078 / −1.110〜−0.027）
- ElasticNet: −0.532（−1.298〜+0.190 / −1.095〜−0.002）
- ランダムフォレスト: −0.763（−1.567〜−0.021 / −1.441〜−0.177）

## 何が翌日の降雪を左右するか

### 線形モデルの標準化係数（seed 42）

特徴量を平均0・標準偏差1に揃えたときの重み。「その項目が1標準偏差大きいと、予測がどれだけ動くか」を表す。
目的変数は log1p 変換後の値なので、係数の単位はcmではない。大きさの比較と符号（+/−）だけを見る。

Ridge の上位（絶対値の大きい順）:
- 今日の青森の降雪量 +0.150
- 弘前の最大風速 +0.145
- 青森の海面気圧 −0.132（気圧が低いほど翌日の雪が多い）
- 季節の cos +0.116（真冬ほど多い）
- 前日からの気圧変化 −0.116（気圧が下がっているほど多い）

ElasticNet が残した16項目: 今日の降雪量 +0.191、海面気圧 −0.144、季節cos +0.124、気圧変化 −0.093、弘前の最大風速 +0.091、青森の平均気温 −0.074、昼に雪 +0.072、弘前の平均気温 −0.066、弘前の最低気温 −0.057、弘前の気温の折れ線 +0.055、弘前の降雪量 +0.053、青森の最低気温 −0.045、弘前の湿度 +0.028、青森の湿度 +0.027、弘前の最多風向（東寄り） +0.004、弘前の気温変化 −0.002。

注意: 項目どうしが強く連動している（気温どうし、降雪量どうしなど）。そのため1つ1つの係数の向きは不安定になる。たとえば「前日の降雪量」がマイナスなのは、今日の降雪量・3日合計と重なっているため。風向も、青森の最大風速の風向は西寄りほど+（−0.016、東寄りほど+の成分がマイナス）とわずかなのに対し、弘前の最多風向は東寄りほど+（+0.063）で、データ分析で見た「西風で雪が多い」と向きがそろっていない。係数1つだけで因果を語らない方がよい。

### permutation importance（評価データ上）

ある項目の値を評価データの中でばらばらに並べ替え、MAEがどれだけ悪くなるか（cm）を測った。悪くなるほど、モデルがその項目に頼っている。50回繰り返して平均した。

1項目ずつ（上位）:
- ランダムフォレスト: 海面気圧 0.348、今日の降雪量 0.227、平均気温 0.106、気圧変化 0.105、寒さ×湿度 0.084
- 勾配ブースティング: 海面気圧 0.311、気圧変化 0.165、今日の降雪量 0.130、平均気温 0.056、平均湿度 0.053
- SVR: 気圧変化 0.112、弘前の最多風向（東寄り） 0.071、今日の降雪量 0.040
- Ridge: 気圧変化 0.125、海面気圧 0.116、今日の降雪量 0.103、昼に雪 0.061

連動した項目は1つずつ並べ替えても、ほかの項目が代わりを務めて小さく出る。そこで、グループごとにまとめて並べ替えた結果も出した（勾配ブースティング / ランダムフォレスト / Ridge / SVR）:
- 気温: 0.448 / 0.582 / 0.561 / 0.539
- 気圧: 0.514 / 0.462 / 0.285 / 0.221
- 降雪・積雪: 0.180 / 0.340 / 0.232 / 0.098
- 季節（暦）: 0.073 / 0.061 / 0.070 / 0.027
- 降水・天気: 0.038 / 0.126 / 0.040 / 0.047

まとめ:
- 翌日の降雪の予測には、今日の「気温」「気圧（低さ・下がり方）」「降雪量」が主に効いている。

- 評価データは151日・大雪日7日と少なく、重要度の値も目安。

## 限界

- 評価データは1冬（151日、大雪日7日）だけ。数字は「この冬では」の結果で、雪の少ない冬・多い冬で変わりうる。大雪日の適合率・再現率は7日しかないため、1日当たるかどうかで大きく動く。
- 学習データも4冬（604日、大雪日25日）と少ない。大雪のような珍しい日を学ぶには足りない。
- 複数の候補から一番良いものを選ぶと、そのスコアは実力より良く出やすい（楽観バイアス）。
  - CVスコアは、100試行の中で一番良いものなので楽観的。
  - 評価データでの手法の順位を見て「この手法が最良」と言うと、さらに楽観的になる。
  - そのため、手法はCVで選び（勾配ブースティング）、評価データでの順位では選んでいない。評価データの上位（ランダムフォレスト）との差も、信頼区間では区別できない。
- 日別の値しか使っていない。低気圧の通過や寒気の流入のタイミングなど、時間単位の動きは見ていない。実際の天気予報は数値予報（大気の物理計算）を使っており、このモデルはその代わりにはならない。
- 予測は「t日の24時に、その日の日別値がそろっている」ことが前提。実際には日別値の確定に時間がかかることがある。
- 量は控えめに出る。log1p変換とMAEでのチューニングの組み合わせは、平均的な誤差は減らすが、大雪の量は小さく出しやすい。大雪の注意喚起に使うなら、別に「大雪かどうか」を当てる分類モデルを作るか、目的に合う指標でチューニングし直す必要がある。
- 今日の降雪量に頼る分、大雪の翌日に予測が大きく出る（1日遅れ）傾向がある。
- 気温の折れ線の境目（2℃）は、評価の冬を含む全期間のデータ分析と一般的な目安から決めた。評価データの情報がわずかに入りうる。ただし折れ線の有無で結果に差はほぼなかった。
- 欠損: 特徴量の欠損は数日分（最大7日、3日間合計の降雪量）で、学習データの中央値で埋めた（勾配ブースティングは欠損のまま扱う）。
